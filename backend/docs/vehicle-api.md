# Stark Group Vehicle Management System (VMS) - Vehicle REST API

Comprehensive specification and guide for the Vehicle REST API service (`stark-vms-backend`).

---

## 1. Overview & Base URL

- **Default Base URL**: `http://localhost:8080/api/vehicles`
- **Default Port**: `8080`
- **Port Configuration**: Override via environment variable `SERVER_PORT` or system property:
  ```bash
  export SERVER_PORT=8081
  # or
  ./gradlew bootRun --args='--server.port=8081'
  ```
- **Content Type**: `application/json`
- **Authentication**: Stateless Bearer JWT via Spring Security. All `/api/vehicles/**` endpoints require an `Authorization: Bearer <access-token>` header obtained from `POST /api/auth/login`.

---

## 2. Startup Configuration & Environment

The backend requires a running PostgreSQL instance, externalized datasource environment variables, and JWT/course-user security parameters. Never hardcode real credentials in tracked files.

```bash
# Database connectivity
export DB_URL="jdbc:postgresql://localhost:5432/stark_vms_db"
export DB_USERNAME="vms_user"
export DB_PASSWORD="your_secure_password"

# Security & JWT configuration (secret must be at least 32 characters)
export JWT_SECRET="your-strong-secret-key-that-is-at-least-32-chars-long!"
export JWT_EXPIRATION_SECONDS=900
export JWT_ISSUER="stark-vms-backend"
export JWT_AUDIENCE="stark-vms-frontend"

# Course user credentials
export COURSE_USER_EMAIL="admin@starkgroup.test"
export COURSE_USER_PASSWORD_HASH="<BCrypt hash generated via ./gradlew hashPassword>"

cd backend
./gradlew bootRun
```

### Fail-Fast Behavior
If any of `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, or `JWT_SECRET` are missing or invalid, application startup aborts with a configuration failure.

## 2.1. Authentication Contract (`POST /api/auth/login`)

- **Method & Path**: `POST /api/auth/login`
- **Security Level**: Public
- **Request Body**:
  ```json
  {
    "email": "admin@starkgroup.test",
    "password": "<entered password>"
  }
  ```
- **Success Status**: `200 OK`
- **Headers**:
  `Cache-Control: no-store, no-cache, must-revalidate, max-age=0`
  `Pragma: no-cache`
- **Response Body**:
  ```json
  {
    "accessToken": "eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...",
    "tokenType": "Bearer",
    "expiresIn": 900,
    "user": {
      "email": "admin@starkgroup.test"
    }
  }
  ```
- **Failure Responses**:
  - `400 Bad Request`: Field validation error (e.g., blank required fields or invalid email syntax).
  - `401 Unauthorized`: Generic error message `"Email or password is incorrect."` (never reveals account existence).

## 3. Vehicle Domain Model & Field Constraints

| Field | Type | Required | Constraints | Description |
|---|---|---|---|---|
| `id` | `Long` | Response only | Positive integer generated by database | Stable unique surrogate identifier |
| `vehicleNumber` | `String` | Yes | Max 64 chars, non-blank, unique | Unique license/fleet identifier (normalized) |
| `company` | `String` | Yes | Max 120 chars, non-blank | Subsidiary company owning the vehicle |
| `type` | `String` | Yes | Max 60 chars, non-blank | Body/chassis type (e.g., Sedan, SUV, Van, Truck) |
| `brand` | `String` | Yes | Max 80 chars, non-blank | Manufacturer brand name (e.g., Tesla, Toyota) |
| `model` | `String` | Yes | Max 120 chars, non-blank | Vehicle model (e.g., Model 3, Corolla) |
| `status` | `String` | Yes | Enum: `ACTIVE`, `INACTIVE`, `MAINTENANCE` | Operational fleet status |

### Vehicle Number Normalization & Uniqueness Rules
- **Rule**: Trim leading and trailing whitespace; convert all letters to uppercase using `Locale.ROOT`; preserve internal spaces, hyphens, and non-Latin characters.
- **Example**: `"  sg-1001 "` becomes `"SG-1001"`.
- **Enforcement**:
  1. *Business Layer*: Checked before persistence; case/whitespace duplicates are rejected immediately with `409 Conflict`.
  2. *Database Layer*: Real unique constraint (`uk_vehicles_vehicle_number`) protects against race conditions.

## 4. Endpoints Specification

### 4.1. Create Vehicle
- **Method & Path**: `POST /api/vehicles`
- **Request Body**: `CreateVehicleRequest` JSON
- **Success Status**: `201 Created`
- **Headers**: `Location: http://localhost:8080/api/vehicles/{id}`
- **Response Body**: `VehicleResponse` JSON

#### Request Example
```json
{
  "vehicleNumber": "SG-1001",
  "company": "Stark Industries",
  "type": "Sedan",
  "brand": "Tesla",
  "model": "Model S",
  "status": "ACTIVE"
}
```

#### Response Example (`201 Created`)
```json
{
  "id": 1,
  "vehicleNumber": "SG-1001",
  "company": "Stark Industries",
  "type": "Sedan",
  "brand": "Tesla",
  "model": "Model S",
  "status": "ACTIVE"
}
```

---

### 4.2. List All Vehicles
- **Method & Path**: `GET /api/vehicles`
- **Success Status**: `200 OK`
- **Response Body**: JSON array of `VehicleResponse` objects.
- **Empty List Behavior**: Returns HTTP `200 OK` with an empty array `[]` (never `404`).

#### Response Example (`200 OK`)
```json

  {

    "type": "Sedan",

  {
    "id": 2,
    "vehicleNumber": "SG-1002",
    "company": "Stark Logistics",
    "type": "Van",
    "brand": "Ford",
    "model": "Transit",
    "status": "MAINTENANCE"
  }
]
```

### 4.3. Get Vehicle by ID
- **Method & Path**: `GET /api/vehicles/{id}`
- **Path Variable**: `id` (must be a positive integer)
- **Success Status**: `200 OK`
- **Error Status**: `404 Not Found` if ID does not exist; `400 Bad Request` if ID $\le 0$ or non-numeric.

#### Response Example (`200 OK`)
```json
{
  "id": 1,
  "vehicleNumber": "SG-1001",
  "company": "Stark Industries",
  "type": "Sedan",
  "brand": "Tesla",
  "model": "Model S",
  "status": "ACTIVE"
}
```

---

### 4.4. Update Vehicle
- **Method & Path**: `PUT /api/vehicles/{id}`
- **Path Variable**: `id` (must be a positive integer)
- **Semantics**: Complete update of the six business fields. PATCH semantics are not supported.
- **Success Status**: `200 OK`
- **Error Status**: `404 Not Found` if record does not exist; `409 Conflict` if updating `vehicleNumber` to one already used by another vehicle; `400 Bad Request` for validation failures.
- **ID Preservation**: The vehicle retains its original generated `id`.

#### Request Example
```json
{
  "vehicleNumber": "SG-1001",
  "company": "Stark Aerospace",
  "type": "SUV",
  "brand": "Tesla",
  "model": "Model X",
  "status": "MAINTENANCE"
}
```

#### Response Example (`200 OK`)
```json
{
  "id": 1,
  "vehicleNumber": "SG-1001",
  "company": "Stark Aerospace",
  "type": "SUV",
  "brand": "Tesla",
  "model": "Model X",
  "status": "MAINTENANCE"
}
```

---

### 4.5. Delete Vehicle
- **Method & Path**: `DELETE /api/vehicles/{id}`
- **Path Variable**: `id` (must be a positive integer)
- **Success Status**: `204 No Content`
- **Response Body**: None (empty body)
- **Error Status**: `404 Not Found` if vehicle does not exist; `400 Bad Request` if ID $\le 0$ or non-numeric.

## 5. Error Contract & Error Codes

All error responses return a standardized, client-safe JSON payload:

```json
{
  "timestamp": "2026-11-03T04:00:00Z",
  "status": 400,
  "code": "VALIDATION_FAILED",
  "message": "Validation failed for request",
  "path": "/api/vehicles",
  "fieldErrors": [
    {
      "field": "vehicleNumber",
      "message": "Vehicle number must not be blank"
    }
  ]
}
```

### Error Code Summary

| HTTP Status | Error Code | Description |
|---|---|---|
| `400 Bad Request` | `VALIDATION_FAILED` | Request payload failed Bean Validation (e.g., blank required fields, exceeding max length, ID $\le 0$). |
| `400 Bad Request` | `MALFORMED_REQUEST` | Invalid JSON syntax or unparseable field values (e.g. invalid `status` enum string). |
| `400 Bad Request` | `INVALID_ARGUMENT_TYPE` | Type mismatch on request parameters (e.g., passing non-numeric `/api/vehicles/abc`). |
| `404 Not Found` | `VEHICLE_NOT_FOUND` | Vehicle with specified `id` was not found. |
| `409 Conflict` | `DUPLICATE_VEHICLE_NUMBER` | A vehicle with the normalized `vehicleNumber` already exists. |
| `405 Method Not Allowed` | `METHOD_NOT_ALLOWED` | Endpoint does not support the HTTP method. Includes `Allow` header. |
| `415 Unsupported Media Type` | `UNSUPPORTED_MEDIA_TYPE` | Request content type is not `application/json`. |
| `500 Internal Server Error` | `INTERNAL_SERVER_ERROR` | Server-side unhandled exception. Details logged safely server-side without leaking stack traces or credentials. |

## 6. Working `curl` Examples

### 1. Create a Vehicle
```bash
curl -i -X POST http://localhost:8080/api/vehicles \
  -H "Content-Type: application/json" \
  -d '{
    "vehicleNumber": "SG-2024-X",
    "company": "Stark Industries",
    "type": "Sedan",
    "brand": "Tesla",
    "model": "Model 3",
    "status": "ACTIVE"
  }'
```

### 2. List All Vehicles
```bash
curl -i http://localhost:8080/api/vehicles
```

### 3. Read One Vehicle by ID
```bash
curl -i http://localhost:8080/api/vehicles/1
```

### 4. Update a Vehicle
```bash
curl -i -X PUT http://localhost:8080/api/vehicles/1 \
  -H "Content-Type: application/json" \
  -d '{
    "vehicleNumber": "SG-2024-X",
    "company": "Stark Industries",
    "type": "SUV",
    "brand": "Tesla",
    "model": "Model Y",
    "status": "MAINTENANCE"
  }'
```

### 5. Duplicate Vehicle Number Rejection (409 Conflict)
```bash
curl -i -X POST http://localhost:8080/api/vehicles \
  -H "Content-Type: application/json" \
  -d '{
    "vehicleNumber": "  sg-2024-x  ",
    "company": "Stark Security",
    "type": "Truck",
    "brand": "Ford",
    "model": "F-150",
    "status": "ACTIVE"
  }'
```

### 6. Invalid Input Rejection (400 Bad Request)
```bash
curl -i -X POST http://localhost:8080/api/vehicles \
  -H "Content-Type: application/json" \
  -d '{
    "vehicleNumber": "",
    "company": "Stark Industries",
    "type": "Sedan",
    "brand": "Tesla",
    "model": "Model S",
    "status": "INVALID_STATUS"
  }'
```

### 7. Delete a Vehicle
```bash
curl -i -X DELETE http://localhost:8080/api/vehicles/1
```
